Overview
Log Collection Failure Alerts notify administrators when configured log sources or agents stop sending logs to Log360 Cloud. This helps detect potential issues early, preventing gaps in log data and ensuring continuous monitoring.
Key features:
Automated health checks - The system evaluates log collection status every 15 minutes.
Profile-based monitoring - Create multiple alert profiles to independently monitor different log sources, agents, or device groups.
Device and application monitoring - Tracks configured applications in addition to devices, providing visibility at both system and application levels.
How it works?
The alert monitors log ingestion from the selected log sources or agents. If logs are not received within the configured time interval, an email notification is sent to the specified recipients. You can customize the notification subject, recipients, and frequency.
Alerts are generated under the following conditions:
Log source not reachable/credential issue
- When the platform is unable to establish communication with the configured log source due to network or authentication errors.
No logs generated -
When no logs are received from the selected source within the defined time threshold.
Collection schedule delayed -
When scheduled log collection exceeds the configured time interval.
Agent stopped/communication delayed
- When an agent stops functioning, fails to upgrade, or does not communicate with the product within the expected duration.
This ensures administrators are promptly notified of log collection disruptions, enabling faster troubleshooting and uninterrupted visibility across monitored environments.
Use cases
1. Managing alerts during business and non-business hours
In environments where support teams operate in shifts or follow defined working hours, time-based notification scheduling ensures alerts are delivered only when the appropriate team is available.
For example, alerts can be restricted to working hours for internal IT teams, or sent during non-working hours to notify on-call staff. Custom schedules allow alignment with specific operational requirements.
2. Ensuring persistent visibility for critical systems
This setting sends notifications at predefined intervals for as long as the failure condition persists.
For example, if the interval is configured as 30 minutes and a log collection failure occurs, the system sends a notification every 30 minutes until the issue is resolved.
This option is suitable in environments where uninterrupted monitoring is critical, as repeated notifications ensure that unresolved issues remain visible and receive timely attention.
3. Minimizing alert fatigue
In environments with many monitored devices, sending only one notification per failure helps reduce unnecessary alert noise.
This ensures administrators are informed of the issue without being overwhelmed by repeated reminders for the same incident
