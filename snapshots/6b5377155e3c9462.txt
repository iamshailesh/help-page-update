Overview
Device groups
in ManageEngine Log360 allow you to organize log sources into groups and manage them together. Instead of configuring each device individually, you can group related devices and perform bulk actions such as updating credentials, changing monitor intervals, and applying configuration settings across all devices in the group at once.
Device groups can be organized by physical location, department, operating system, or any other criteria that suits your environment. The
Technician and Roles
lets you assign technicians to specific device groups, so each technician only has access to the devices relevant to their role.
This page explains how to create and manage device groups, configure group-level settings, and perform bulk actions on devices in ManageEngine Log360.

How Windows devices are classified?
When a Windows device is added as a log source, Log360 automatically classifies it as either a
workstation
or a
server
based on its operating system type:
Devices running
Windows Workstation editions
(such as Windows 10 or Windows 11) are automatically assigned to the
Windows Workstation
group.
Devices running
Windows Server editions
(such as Windows Server 2019 or 2022) are assigned to the
Windows Group
.
This automatic classification helps you immediately segregate endpoint devices from servers without any manual configuration, making it easier to apply different monitoring policies to each category.
Use cases
Device groups allow you to align your log management with how your organization is actually structured. Common scenarios include:
Location-based management
Group devices by physical site for example, New York Office or London Branch to apply region-specific monitoring policies or manage scheduled log collection across different time zones.
Departmental restrictions
Create groups such as Finance Servers or HR Workstations to isolate log access by department. This is especially useful when combined with Technician & Role settings, where a department's IT staff should only see logs from their own devices.
OS or application type
Build groups based on operating system (e.g., Linux Servers, Windows Workstations) or application log type (e.g., IIS Servers, SQL Servers) to apply targeted configurations or monitor intervals relevant to that technology.
Role-Based Access Control (RBAC) with Technician & Roles
Device groups integrate directly with the
Technician and Roles
feature. You can assign specific technicians to manage only the device groups relevant to their role. For example, a junior analyst in the finance team can be restricted to viewing logs only from the Finance Servers group, while a senior admin retains access across all groups. This ensures accountability and limits unnecessary exposure to sensitive log data.
Key considerations
Single group membership:
A log source can belong to only one device group at a time. If you add a log source to a new group, it is automatically removed from its previous group.
Log type and device groups:
Device groups are device-based, not log-type-based. A single device (for example, a Windows server running both IIS and SQL) belongs to one group, regardless of how many log types it generates. To organize by log type, use filters and views within the product rather than separate groups.
Default group:
Any log source not assigned to a specific group is placed in the
DefaultGroup
automatically.
Prerequisites
User Role:
You must be logged in as a user with the Admin role to access the Device Groups page and allocate devices to groups.

Delete device group
This action removes the selected device group from the product.
NOTE
A device group cannot be deleted if it is the only device group assigned to a technician. In such cases, the following message is displayed: Cannot delete some of the groups associated to certain users. Assign another device group to the technician or remove the technician's association with the device group before attempting to delete it.
Once deleted, the associated devices will be removed from the following configurations, which must be reconfigured manually:
Custom Reports
Compliance
Alert Profiles
Archive Policy
Log Collection Filter
Log Collection Failure Alert
